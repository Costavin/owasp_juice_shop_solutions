# Extra Language

First, we need to check how language is managed. With burpsuite, we can intercept an initial `GET` request to `/assets/i18n/en.json`. The first thing we can notice is the nomenclature `i18n`, which refers to architectural practice for the design of software that can be adapted to different languages. We can generate a list of two character words, but unfrotunately, other than `en.json`, we don't get any other significant value. Among all other requests, we can notice another `GET` request to the endpoint `/rest/languages`, where we can obtain an additional understanding on how languages are fetched. It seems they follow the pattern `xy_ZW`. However, another bruteforce search over all the possible combinations doesn't lead to nowhere. One of the hints suggested to search for a lits of available languages. Then exists a language that doesn't fall into the pattern `xy_ZW`. After some research, we can find that in software development and internazionalization (i18n), languages are identified by using ISO 639-1 codes, or BCP-47 tags, and that the choice for the underscore is usually preferred for backend file systems. Moreover, there are different versions of the ISO 639-*, where are dedined additional languages. After a small search on available languages, we can find in Duolingo that exist other esotic anguages, like the High Valyrian, or the Klingon. These languages have an ISO 639-2 representation, so we can try them. As we don't know the part following the underscore, we can brute force them for each new language we've found. With great surprise, we find that the hidden language was ineed the Klingon one.
